¿Cómo funciona la Codificación Base64URL?

1. JSON en Texto Plano

Los datos del Header y Payload se estructuran en objetos JSON estándar.

2. Conversión Base64 Estándar

Se convierten los caracteres a bytes UTF-8 y luego a codificación Base64.

3. Reemplazo a Base64URL Safe

Se reemplaza + por -, / por _ y se omiten los rellenos = para viajar seguro en URLs/HTTP.

Cifrado Simétrico (HS256 - HMAC)

Misma clave para Firmar y Verificar

  • El Auth Service y todos los Microservicios deben compartir el mismo secreto (Secret Key).
  • Rápido computacionalmente pero mayor riesgo: Si un microservicio secundario se vulnera, la clave maestra queda expuesta.
Auth Service [Firma con Secret] 🔑 ──► Microservicio A [Verifica con MISMO Secret] 🔑

Cifrado Asimétrico (RS256 / ES256)

Par de Claves Pública y Privada

  • El Auth Service firma los tokens con la Clave Privada secreta.
  • Los Microservicios descargan la Clave Pública vía un endpoint público JWKS (/.well-known/jwks.json) y verifican sin conocer la clave privada.
Auth Service [Firma con Clave Privada 🔐] ──► Microservicio A [Verifica con Clave Pública JWKS 🔓]

Comparativa: Access Token vs. Refresh Token

Atributo Access Token (JWT) Refresh Token
Propósito Autenticar peticiones a los Microservicios. Solicitar un nuevo Access Token al expirar el actual.
Tiempo de Vida (TTL) Muy Corto (~15 minutos) Largo (~7 a 30 días)
Almacenamiento Recomendado Memoria del Cliente / Estado de aplicación (no localStorage). Cookie segura HttpOnly, Secure, SameSite=Strict.
Estado (Statefulness) Stateless (No requiere base de datos). Stateful (Guardado en Redis / BD para poder revocarse).

Mecanismo de Rotación de Refresh Tokens (Token Rotation)

Prevención de robo: Cada vez que se usa un Refresh Token, este se destruye y se emite uno nuevo. Si un atacante intenta reutilizar un token viejo, se invalida toda la familia de tokens.

1. Refresh Normal RT_01

El cliente legítimo envía RT_01 al Auth Service para renovar acceso.

2. Rotación Exitosa RT_02 Emitido

Auth Service invalida RT_01, emite el nuevo RT_02 y un nuevo JWT.

3. Detección de Robo Reutilización

Si un atacante usa el viejo RT_01, el sistema detecta la anomalía y revoca RT_02 e inhabilita la sesión.
